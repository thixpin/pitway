# Requirement: Sequential Task Execution via Subagent

When a milestone contains multiple tasks, PitWay should allow an agent to delegate task execution to a subagent that processes an assigned task sequence sequentially, so the main agent can preserve its context for milestone-level planning, review, and orchestration.

* The main agent remains responsible for milestone orchestration and overall decisions.
* A delegated execution subagent processes its assigned tasks sequentially according to their dependency/order constraints.
* The existing task graph may continue to execute independent tasks in parallel; subagent execution must not serialize tasks that are otherwise eligible for parallel execution.
* Each task follows the existing PitWay task lifecycle, including execution, verification, completion, and evidence recording.
* Task-level token usage must continue to be captured and persisted for every task executed through a subagent, using the same usage semantics as the existing execution flow.
* Usage must remain attributable to the correct task; usage from one task must not be incorrectly merged into another task or into the milestone-level total.
* A task that cannot be completed or verified successfully must stop the delegated sequence rather than silently continuing past the failure.
* Completed task results, verification evidence, status, and usage remain visible to the main agent.
* The main agent can resume or continue the task sequence after the subagent reports its result.
* Existing milestone, task, verification, journal, usage-tracking, and governance rules remain unchanged.
* The feature must not require every task to run through a subagent; existing inline execution remains supported.
* Subagent delegation is an optional execution strategy and must not change the semantics of the underlying task lifecycle.
